## 1. 시스템 구성

EC2 한 대에 Nginx(호스트 설치)와 Docker Compose 스택을 함께 올리는 구성입니다.

```
Android 앱 (Expo / React Native)
  │  HTTPS
  ▼
Nginx (호스트, 80 → 443 리다이렉트, Let's Encrypt)
  │
  ├── /           → dotori-backend  (Spring Boot, 8080)
  │                   ├── dotori-postgres  (PostgreSQL, 5432)
  │                   ├── dotori-redis     (Redis, 6379)
  │                   ├── dotori-rabbitmq  (RabbitMQ, 5672 / 관리 UI 15672)
  │                   └── dotori-ai        (FastAPI, 8000, 외부 미노출)
  │                         └── 같은 PostgreSQL · RabbitMQ 공유
  │
  └── /jenkins/   → Jenkins (호스트 설치, 9090, --prefix=/jenkins)
```

- 백엔드·AI 서버 이미지는 Jenkins가 빌드해 **AWS ECR**에 push하고, 서버는 그 이미지를 pull해서 실행합니다.
- AI 서버는 Spring만 호출하는 내부 서비스입니다. 호스트 포트를 열지 않고 compose 네트워크 안에서
  `http://ai:8000` 으로만 접근하며, 두 서버는 같은 값의 `INTERNAL_TOKEN` 으로 인증합니다.
- 서버 구성(패키지 설치, Nginx, 방화벽, compose 파일 배치, 컨테이너 기동)은 `dotori-ansible` playbook 한 번으로 끝납니다.

## 3. 사전 준비

### 3-1. AWS

| 항목 | 값 |
| --- | --- |
| EC2 | Ubuntu 22.04 이상 |
| 보안그룹 인바운드 | 22(SSH), 80(HTTP), 443(HTTPS), 15672(RabbitMQ 관리 UI) |
| 리전 | `ap-northeast-2` (서울) |
| ECR 레포지토리 | `dotori-backend`, `dotori-ai` |
| S3 버킷 | `s15p21a505dotori` (비공개) |
| IAM 사용자 | ECR push/pull 용 1개, S3 업로드용 1개 (**서로 다른 사용자**) |

ECR 레포지토리는 최초 1회 생성합니다.

```bash
aws ecr create-repository --repository-name dotori-backend --region ap-northeast-2
aws ecr create-repository --repository-name dotori-ai      --region ap-northeast-2
```

> 8080(앱), 5432(PostgreSQL), 6379(Redis), 5672(AMQP)는 컨테이너 간 내부 통신용이라 보안그룹에서
> 열 필요가 없습니다. 9090(Jenkins)도 Nginx `/jenkins/` 경로로만 접근합니다.

## 4. 빌드

### 4-1. 저장소 클론

```bash
git clone https://lab.ssafy.com/s15-fintech-finance-sub1/S15P21A505.git
cd S15P21A505
```

### 4-2. 백엔드 (Spring Boot)

운영 배포는 Docker 멀티스테이지 빌드를 사용합니다(`backend/Dockerfile`). 컨테이너 안에서 Gradle로
`bootJar` 를 만들고, JRE 이미지에 jar만 담아 non-root 유저(`dotori`)로 실행합니다.

```bash
cd backend
chmod +x gradlew                      # 8장 "gradlew 실행 권한" 참고
docker build -t dotori-backend .
```

jar만 필요할 때는 다음과 같이 빌드합니다(JDK 21 필요).

```bash
cd backend
./gradlew clean bootJar -x test       # 결과물: build/libs/dotori-0.0.1-SNAPSHOT.jar
java -jar build/libs/*.jar
```

> 테스트는 로컬 PostgreSQL을 사용합니다(H2 미사용). 테스트까지 돌리려면 먼저 루트에서
> `docker compose -f docker-compose.local.yml up -d` 로 로컬 DB(호스트 5433)를 띄우세요.

### 4-3. AI 서버 (FastAPI)

```bash
docker build -t dotori-ai AI
# 테스트 (in-memory SQLite + mock 사용, 외부 의존 없음)
docker run --rm -v "$PWD/AI:/src:ro" -w /src -e PYTHONPATH=/src dotori-ai pytest -q -p no:cacheprovider
```

### 4-4. 프론트엔드 (Android 앱)

```bash
cd frontend
npm ci
cp .env.example .env                  # EXPO_PUBLIC_API_URL=https://j15a505.p.ssafy.io
# Firebase 콘솔에서 받은 google-services.json 을 frontend/ 에 둔다 (커밋되지 않음)
```

- 개발 실행: `npx expo run:android` (에뮬레이터 또는 USB 연결 기기)
- APK 빌드: `android/` 네이티브 프로젝트는 커밋하지 않으므로 prebuild로 생성한 뒤 Gradle로 빌드합니다.

```bash
npx expo prebuild -p android --clean
cd android && ./gradlew assembleRelease   # 결과물: android/app/build/outputs/apk/release/
```

## 7. 배포 절차

### 7-1. 최초 배포

```bash
# 1) 배포 저장소 준비
git clone <dotori-ansible 저장소>
cd dotori-ansible
ansible-galaxy collection install -r requirements.yml

# 2) 설정 파일 작성 (환경변수.md 의 "배포 설정" 절 참고)
cp inventory/hosts.ini.example inventory/hosts.ini
cp group_vars/all.yml.example  group_vars/all.yml
cp group_vars/vault.yml.example group_vars/vault.yml
ansible-vault encrypt group_vars/vault.yml

# 3) Firebase 서비스 계정 키를 저장소 루트에 두고 all.yml 의 fcm_credentials_src 에 파일명 기입
#    (Firebase 콘솔 > 프로젝트 설정 > 서비스 계정 > 새 비공개 키 생성)

# 4) AI 이미지가 아직 ECR에 없으면 all.yml 에서 enable_ai: false

# 5) 실행
ansible-playbook playbook.yml --ask-vault-pass
```

playbook이 수행하는 작업은 다음과 같습니다.

1. Docker Engine·Compose, Jenkins(+JDK 17), Nginx, certbot, AWS CLI v2 설치
2. Nginx 설정 배포 → Let's Encrypt 인증서 발급 → HTTPS 설정 재배포
3. UFW 규칙 적용
4. ECR 로그인, `/opt/dotori` 에 `docker-compose.yml`·`.env`·FCM 키 배치
5. `docker compose` 로 이미지 pull 후 전체 스택 기동
6. Jenkins 초기 비밀번호 출력

### 7-2. DB 스키마 적용

PostgreSQL 컨테이너 볼륨이 비어 있는 상태로 처음 떴다면 DB는 비어 있습니다. 스키마와 초기 데이터를 넣습니다.

```bash
# 로컬 PC에서 서버로 SQL 복사
scp -i <key.pem> backend/docker/initdb/*.sql ubuntu@<EC2_IP>:/tmp/

# 서버에서 실행
ssh -i <key.pem> ubuntu@<EC2_IP>
docker exec -i dotori-postgres psql -U dotori -d dotori_town < /tmp/01-schema.sql
docker exec -i dotori-postgres psql -U dotori -d dotori_town < /tmp/02-seed-investment-products.sql
```

### 7-3. 이후 배포

- AI 서버: `dev` 브랜치에 `AI/**` 변경이 push되면 GitLab webhook으로 Jenkins가 이미지를 빌드·push하고 `ai` 컨테이너만 재기동합니다.
- 백엔드: Jenkins 파이프라인으로 ECR에 이미지를 push한 뒤 `app` 컨테이너를 갱신합니다(파이프라인 상세는 [서버설정.md](서버설정.md#3-jenkins) 에 추후 첨부).
- 설정값을 바꿨을 때는 playbook을 다시 실행합니다. 바뀐 부분만 반영됩니다.

### 7-4. 배포 확인

```bash
docker compose -f /opt/dotori/docker-compose.yml ps
docker compose -f /opt/dotori/docker-compose.yml logs -f app
curl -s https://j15a505.p.ssafy.io/actuator/health          # {"status":"UP"}
docker compose -f /opt/dotori/docker-compose.yml exec app wget -qO- http://ai:8000/health
sudo nginx -t && sudo systemctl status nginx
```

- API 문서(Swagger UI): `https://j15a505.p.ssafy.io/swagger-ui/index.html`
- RabbitMQ 관리 UI: `http://<EC2_IP>:15672`

### 7-5. 롤백

Jenkins는 커밋 해시 태그와 `latest` 를 함께 push합니다.

```bash
aws ecr describe-images --repository-name dotori-ai --region ap-northeast-2 \
    --query 'sort_by(imageDetails,&imagePushedAt)[-5:].imageTags'
cd /opt/dotori && AI_IMAGE_TAG=<커밋해시> docker compose up -d ai
cd /opt/dotori && IMAGE_TAG=<커밋해시> docker compose up -d app
```

## 8. 배포 특이사항

| 항목 | 내용 |
| --- | --- |
| **gradlew 실행 권한** | `backend/gradlew` 가 Git에 실행 권한 없이(`100644`) 올라가 있습니다. 클론한 그대로 `./gradlew` 를 실행하거나 `docker build` 하면 `permission denied` 가 납니다. 빌드 전에 `chmod +x backend/gradlew` 하거나 `sh gradlew ...` 로 실행하세요. |
| **AI 서버 최초 배포 순서** | `enable_ai: true` 인데 ECR에 `dotori-ai` 이미지가 없으면 compose pull이 실패해 **백엔드를 포함한 스택 전체**가 뜨지 않습니다. ① ECR 레포 생성 → ② Jenkins로 이미지 push(마지막 배포 단계만 실패, push는 완료) → ③ `enable_ai: true` 로 playbook 실행 순서를 지킵니다. |
| **DB 스키마 관리** | JPA `ddl-auto: none` 입니다. 스키마 원본은 `backend/docker/initdb/01-schema.sql` 하나이고, 이미 만들어진 DB의 변경분은 `backend/docker/migration/*.sql` 을 **손으로** 실행합니다(여러 번 실행해도 안전하게 작성됨). |
| **JDBC `stringtype=unspecified`** | PostgreSQL 네이티브 ENUM 컬럼에 `@Enumerated(STRING)` 값을 넣기 위해 JDBC URL에 붙어 있습니다. 빠지면 INSERT가 타입 오류로 실패합니다. |
| **FCM 키 파일** | `FCM_CREDENTIALS_PATH` 가 비어 있으면 `firebaseMessaging` 빈 생성이 실패해 **앱이 기동하지 않습니다.** 컨테이너가 non-root로 돌기 때문에 키 파일 권한은 `0444` 여야 합니다(`0400` 이면 AccessDenied). |
| **AWS 자격증명 두 쌍** | ECR pull용(`vault_ecr_*`)과 S3 업로드용(`aws_access_key_id` 등)은 서로 다른 IAM 사용자입니다. 변수 이름이 겹치면 `vault.yml` 이 `all.yml` 을 덮어써 ECR 로그인이 엉뚱한 키로 시도됩니다(`no_log` 라 로그에 단서가 남지 않음). |
| **HTTPS와 쿠키** | `COOKIE_SECURE=true` 인데 HTTPS가 없으면 브라우저가 쿠키를 저장하지 않습니다. 도메인 없이 HTTP로만 운영할 때는 `false` 로 바꿉니다. |
| **INTERNAL_TOKEN** | Spring과 AI 서버에 **같은 값**이어야 합니다. AI 서버는 값이 비어 있으면 검증을 건너뛰므로 운영에서는 반드시 채웁니다. |
| **QA 트리거** | `QA_TRIGGER_ENABLED=true` 면 `/api/v1/internal/qa/**` 로 배치(할 일 반복, 예적금 정산 등)를 즉시 실행할 수 있습니다. 운영에서는 `false` 로 둡니다. |
| **업로드 용량** | 인증 사진 한도는 Spring 파일 10MB / 요청 12MB, Nginx `client_max_body_size 20m` 입니다. Nginx 값을 Spring보다 작게 줄이면 413이 납니다. |
| **타임존** | 모든 컨테이너 `TZ=Asia/Seoul`, Hibernate `jdbc.time_zone=Asia/Seoul`. 배치·거래 시각이 KST 기준입니다. |
| **데이터 영속성** | PostgreSQL·Redis·RabbitMQ 데이터는 Docker 볼륨에 있습니다. `docker compose down -v` 는 **데이터를 모두 삭제**합니다. |
| **앱 API 주소** | `EXPO_PUBLIC_API_URL` 은 빌드 시 번들에 박힙니다. 서버 주소가 바뀌면 APK를 다시 빌드해야 합니다. |
| **민감 파일** | `inventory/hosts.ini`, `group_vars/all.yml`, `group_vars/vault.yml`, `*.pem`, `*firebase-adminsdk*.json`, `google-services.json`, `.env` 는 `.gitignore` 로 커밋되지 않습니다. |
