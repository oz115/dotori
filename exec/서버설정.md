# 서버 설정 (Nginx · Docker Compose · Jenkins · 방화벽)

[← 포팅 매뉴얼로 돌아가기](포팅메뉴얼.md)

아래 설정은 모두 `dotori-ansible` 템플릿으로 생성되므로 **손으로 만들 필요는 없습니다.** 확인용으로 운영 값을 적어 둡니다.

## 1. Nginx — `/etc/nginx/sites-available/dotori.conf`

`templates/nginx-dotori.conf.j2` 에서 생성합니다. 기본 사이트(`sites-enabled/default`)는 비활성화합니다.

```nginx
server {
    listen 80;
    server_name j15a505.p.ssafy.io;

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl http2;
    server_name j15a505.p.ssafy.io;

    ssl_certificate     /etc/letsencrypt/live/j15a505.p.ssafy.io/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/j15a505.p.ssafy.io/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 20m;          # 인증 사진 업로드 (Spring 쪽 한도는 파일 10MB / 요청 12MB)

    location = /jenkins {
        return 301 /jenkins/;
    }

    location /jenkins/ {
        proxy_pass http://127.0.0.1:9090/jenkins/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-Port $server_port;
        proxy_redirect http://127.0.0.1:9090/jenkins/ $scheme://$host/jenkins/;
        proxy_max_temp_file_size 0;
        proxy_buffering off;
        proxy_request_buffering off;
    }

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

인증서 갱신 시 Nginx가 자동으로 reload되도록 `/etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh` 가 등록됩니다.

## 2. Docker Compose — `/opt/dotori/docker-compose.yml`

`templates/docker-compose.yml.j2` 에서 생성합니다. 요약:

| 서비스 | 컨테이너 | 이미지 | 호스트 포트 | 볼륨 | 헬스체크 |
| --- | --- | --- | --- | --- | --- |
| `postgres` | `dotori-postgres` | `postgres:16-alpine` | 5432 | `dotori-postgres-data` | `pg_isready` |
| `redis` | `dotori-redis` | `redis:7-alpine` | 6379 | `dotori-redis-data` | `redis-cli ping` |
| `rabbitmq` | `dotori-rabbitmq` | `rabbitmq:3-management-alpine` | 5672, 15672 | `dotori-rabbitmq-data` | `rabbitmq-diagnostics ping` |
| `app` | `dotori-backend` | `${ECR_REPO}:${IMAGE_TAG}` | 8080 | `./secrets/firebase-adminsdk.json` (ro) | — |
| `ai` | `dotori-ai` | `${AI_ECR_REPO}:${AI_IMAGE_TAG}` | 없음 | 없음 (stateless) | `GET /health` (Dockerfile 내장) |

- `app`, `ai` 는 postgres·redis·rabbitmq가 `service_healthy` 가 된 뒤 기동합니다.
- 모든 컨테이너는 `TZ=Asia/Seoul`, `restart: unless-stopped`, 네트워크 `dotori-network`(bridge)를 씁니다.
- 이미지 주소는 같은 디렉토리의 `/opt/dotori/.env` 로 치환됩니다. 단, 백엔드 파이프라인은 `.env.backend` 를 `--env-file` 로 따로 넘깁니다 ([3. Jenkins](#3-jenkins) 참고).

```
ECR_REPO=<AWS 계정 ID>.dkr.ecr.ap-northeast-2.amazonaws.com/dotori-backend
IMAGE_TAG=latest
AI_ECR_REPO=<AWS 계정 ID>.dkr.ecr.ap-northeast-2.amazonaws.com/dotori-ai
AI_IMAGE_TAG=latest
```

## 3. Jenkins

- apt(`pkg.jenkins.io/debian-stable`)로 호스트에 설치하고 `openjdk-17-jdk` 로 구동합니다.
- systemd override(`/etc/systemd/system/jenkins.service.d/override.conf`):

  ```ini
  [Service]
  Environment="JENKINS_PORT=9090"
  Environment="JENKINS_PREFIX=/jenkins"
  ```

- `jenkins` 사용자를 `docker` 그룹에 추가해 파이프라인이 같은 서버의 compose를 직접 조작합니다.
- 초기 관리자 비밀번호: `sudo cat /var/lib/jenkins/secrets/initialAdminPassword` (playbook 실행 결과에도 출력)
- 접속: `https://j15a505.p.ssafy.io/jenkins/`
- 추가 플러그인: **GitLab**(push/MR 트리거), **SSH Agent**(백엔드 배포 단계의 `sshagent`)

GitLab 연동:

1. Jenkins 관리 → System → GitLab connections 에 `lab.ssafy.com` 연결을 등록합니다.
2. Job을 한 번 저장(Save)하면 GitLab 트리거가 활성화됩니다.
3. GitLab 저장소 Settings → Webhooks 에 `https://j15a505.p.ssafy.io/jenkins/project/<JOB_NAME>` 을 등록합니다.
   9090 포트는 UFW에서 닫혀 있으므로 반드시 Nginx(`/jenkins/`) 경유 주소를 씁니다.

Credentials:

| ID | 종류 | 값 | 사용처 |
| --- | --- | --- | --- |
| `aws-ecr-credentials` | Username with password | Username = ECR IAM Access Key ID, Password = Secret Access Key | AI · 백엔드 |
| `gitlab-credentials` | Username with password (또는 Access Token) | GitLab 계정 / Personal Access Token | 백엔드 (Checkout) |
| `deploy-server-ssh-key` | SSH Username with private key | Username = `ubuntu`, 배포 서버 접속용 개인키 | 백엔드 (Deploy) |

파이프라인 Job:

| Job | 정의 방식 | 브랜치 | 트리거 | 동작 |
| --- | --- | --- | --- | --- |
| AI 서버 | Pipeline script from SCM (`AI/Jenkinsfile`) | `*/dev` | GitLab webhook (Push) | `AI/**` 변경 시 빌드 → pytest → ECR push(커밋 해시 + `latest`) → `docker compose up -d ai` → 헬스체크 |
| 백엔드 | Pipeline script (아래 스크립트를 Job에 직접 붙여넣기) | `*/master` | GitLab webhook (Push, Merge Request) | `backend/**` 변경 시 `./gradlew clean build`(JUnit 결과 수집) → ECR push(커밋 해시 + `latest`) → SSH로 배포 서버 접속 → `docker compose up -d app` |

백엔드 파이프라인 흐름:

| 단계 | 내용 |
| --- | --- |
| Checkout | `gitlab-credentials` 로 `master` 체크아웃 |
| Prepare | `git rev-parse --short HEAD` 를 `IMAGE_TAG` 로 사용 |
| Build & Test | `backend/` 에서 `./gradlew clean build`, `backend/build/test-results/test/*.xml` 을 JUnit 리포트로 수집 |
| ECR Login & Push | ECR 로그인 → `dotori-backend` 레포가 없으면 생성 → `backend/Dockerfile` 로 빌드 후 `:<커밋해시>`, `:latest` push |
| Deploy | Jenkins에서 ECR 토큰을 받아 `deploy-server-ssh-key` 로 `ubuntu@j15a505.p.ssafy.io` 접속 → 서버에서 ECR 로그인 → `/opt/dotori/.env.backend` 에 `ECR_REPO`, `IMAGE_TAG` 기록 → `docker compose --env-file .env.backend pull app` / `up -d app` |

- `Build & Test` 이후 단계는 모두 `when { changeset "backend/**" }` 라서 백엔드 변경이 없는 push는 체크아웃만 하고 끝납니다. 변경 내역이 비어 있는 **Job의 첫 빌드도 건너뛰므로**, 최초 배포는 백엔드 변경이 포함된 push로 한 번 더 트리거합니다.
- 백엔드는 AI와 달리 `/opt/dotori/.env` 가 아니라 `/opt/dotori/.env.backend` 를 `--env-file` 로 넘겨 이미지 태그를 치환합니다. `--env-file` 을 주면 `.env` 는 읽히지 않으므로 이때 `AI_*` 변수 미설정 경고가 나오지만 `app` 서비스만 갱신하므로 영향은 없습니다.
- 롤백: 서버에서 `.env.backend` 의 `IMAGE_TAG` 를 이전 커밋 해시로 바꾸고 `docker compose --env-file .env.backend up -d app` 을 실행합니다.

<details>
<summary>백엔드 파이프라인 스크립트 (Jenkins Job → Pipeline → Definition: Pipeline script)</summary>

`AWS_ACCOUNT_ID` 는 ansible `group_vars/all.yml` 의 `aws_account_id` 와 같은 값으로 채웁니다.

```groovy
pipeline {
    agent any

    triggers {
        gitlab(
            triggerOnPush: true,
            triggerOnMergeRequest: true,
            triggerOpenMergeRequestOnPush: 'never',
            branchFilterType: 'NameBasedFilter',
            includeBranchesSpec: 'master'
        )
    }

    environment {
        GIT_REPO_URL       = "https://lab.ssafy.com/s15-fintech-finance-sub1/S15P21A505.git"
        GIT_BRANCH         = "master"
        GIT_CREDENTIALS_ID = "gitlab-credentials"
        // ansible group_vars/all.yml의 aws_region/aws_account_id와 동일해야 함
        AWS_REGION     = "ap-northeast-2"
        AWS_ACCOUNT_ID = "<AWS 계정 ID>"
        ECR_REGISTRY   = "${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com"
        IMAGE_NAME     = "dotori-backend"
        ECR_REPO       = "${ECR_REGISTRY}/${IMAGE_NAME}"
        DEPLOY_USER    = "ubuntu"
        DEPLOY_HOST    = "j15a505.p.ssafy.io"
        // Ansible의 app_dir와 동일해야 함
        DEPLOY_PATH    = "/opt/dotori"
    }

    stages {
        stage('Checkout') {
            steps {
                checkout([
                    $class: 'GitSCM',
                    branches: [[name: "*/${GIT_BRANCH}"]],
                    userRemoteConfigs: [[
                        url: "${GIT_REPO_URL}",
                        credentialsId: "${GIT_CREDENTIALS_ID}"
                    ]]
                ])
            }
        }

        stage('Prepare') {
            steps {
                script {
                    env.IMAGE_TAG = sh(script: "git rev-parse --short HEAD", returnStdout: true).trim()
                }
            }
        }

        stage('Build & Test') {
            when { changeset "backend/**" }
            steps {
                dir('backend') {
                    sh 'chmod +x ./gradlew'
                    sh './gradlew clean build'
                }
            }
            post {
                always {
                    junit testResults: 'backend/build/test-results/test/*.xml', allowEmptyResults: true
                }
            }
        }

        stage('ECR Login & Push') {
            when { changeset "backend/**" }
            steps {
                dir('backend') {
                    withCredentials([usernamePassword(credentialsId: 'aws-ecr-credentials', usernameVariable: 'AWS_ACCESS_KEY_ID', passwordVariable: 'AWS_SECRET_ACCESS_KEY')]) {
                        sh """
                            aws ecr get-login-password --region \$AWS_REGION | docker login --username AWS --password-stdin \$ECR_REGISTRY
                            aws ecr describe-repositories --repository-names \$IMAGE_NAME --region \$AWS_REGION || aws ecr create-repository --repository-name \$IMAGE_NAME --region \$AWS_REGION
                            docker build -t \$ECR_REPO:\$IMAGE_TAG -t \$ECR_REPO:latest .
                            docker push \$ECR_REPO:\$IMAGE_TAG
                            docker push \$ECR_REPO:latest
                        """
                    }
                }
            }
        }

        stage('Deploy') {
            when { changeset "backend/**" }
            steps {
                withCredentials([usernamePassword(credentialsId: 'aws-ecr-credentials', usernameVariable: 'AWS_ACCESS_KEY_ID', passwordVariable: 'AWS_SECRET_ACCESS_KEY')]) {
                    script {
                        env.ECR_TOKEN = sh(script: "aws ecr get-login-password --region \$AWS_REGION", returnStdout: true).trim()
                    }
                }
                // docker-compose.yml의 app 이미지는 ${ECR_REPO}:${IMAGE_TAG} 형태
                sshagent(credentials: ['deploy-server-ssh-key']) {
                    sh """
                        ssh -o StrictHostKeyChecking=no \$DEPLOY_USER@\$DEPLOY_HOST "
                          cd \$DEPLOY_PATH &&
                          echo '\$ECR_TOKEN' | docker login --username AWS --password-stdin \$ECR_REGISTRY &&
                          echo 'ECR_REPO=\$ECR_REPO' > .env.backend &&
                          echo 'IMAGE_TAG=\$IMAGE_TAG' >> .env.backend &&
                          docker compose --env-file .env.backend -f docker-compose.yml pull app &&
                          docker compose --env-file .env.backend -f docker-compose.yml up -d app
                        "
                    """
                }
            }
        }
    }

    post {
        always {
            sh 'docker logout "$ECR_REGISTRY" || true'
        }
        success {
            echo "Backend deployed: ${ECR_REPO}:${IMAGE_TAG}"
        }
        failure {
            echo "Backend pipeline failed"
        }
    }
}
```

| 9090 | 규칙 삭제 (Nginx 경유로만 접근) |
